# PyForge 依赖图组件

`depgraph.py` 提供 `DependencyGraph`：固定节点集合上的依赖图组件。
节点是 block，边 `u -> v` 表示 u 依赖 v。组件只维护当前依赖；
版本、权限及其他发布字段由调用方验证。

## 接口

- `DependencyGraph(graph)`：从无环图 `{节点: [直接依赖...]}` 创建，
  创建时做一次全图拓扑排序（迭代实现，10 万长链不溢出调用栈）。
- `replace_batch(changes)`：原子替换最多 100 个节点的完整直接依赖列表
  （每节点最多 15 条，空列表表示清除）。`changes` 接受 dict 或
  `(节点, 依赖列表)` 对序列。成功返回 `None`；失败返回候选图中的一个环
  （首尾相同、中间节点不重复、每条边都真实存在于候选图）。
- `dependencies(node)`：返回当前已提交直接依赖的新列表，
  调用方修改返回值不影响组件状态。

## 批次原子性

`replace_batch` 先归一化批次（去重、校验），再按边差分分两个阶段执行：

1. **先删**：删除所有"旧有而新无"的边。删边不会成环；先删保证
   后续成环判断不会被"即将删除"的旧边干扰（例如同批撤 A->B、加 B->A
   必须成功）。
2. **后加**：逐条加入新边，每条做增量成环检查。任一时刻的中间图都是
   候选图（旧图 + 全部替换）的子图，因此：
   - 候选图无环 ⇒ 所有中间图无环 ⇒ 检查不会误报，批次被接受；
   - 候选图有环 ⇒ 环上至少有一条新边，当环上最后一条新边加入时，
     环的其余边已全部就位，检查必然发现它，批次被拒绝。

   接受与否只取决于候选图本身，与批次条目的排列无关。

失败时按操作日志反向撤销本批已做的边修改（最多批次规模的边），
不保存整图副本。拓扑序在失败批次中可能被重排，但它仍是旧图的有效
拓扑序（边更少的图继承原序），无需还原；因此拒绝后的已提交依赖与
后续批次判断与本批从未发生时完全一致。

## 增量检查的正确性

组件维护拓扑序 `rank`，不变式：每条已提交边 `u -> v` 满足
`rank[u] > rank[v]`。新边 `u -> v` 成环当且仅当已存在路径 `v ⇝ u`。

- `rank[u] > rank[v]`：路径 `v ⇝ u` 上 rank 严格递减，要求
  `rank[v] > rank[u]`，矛盾，故不可能成环，O(1) 接受（性能测试中的
  前向边全部走此分支）。
- 否则只需在 rank 区间 `[rank[u], rank[v]]` 内从 v 前向搜索 u
  （区间外节点不可能出现在该路径上）。找到 u 即得环：
  新边 `u -> v` 加上搜索父指针还原出的路径 `v ⇝ u`，环上每条边
  都来自候选图。找不到时把区间内"v 可达的"与"可达 u 的"两组节点
  按旧 rank 整体重排（Pearce-Kelly），即恢复不变式。

搜索与重排只触及受影响区间内的边，不扫描全图、不复制全部依赖、
不预存全体节点对的可达关系；搜索按节点去重（visited 集合），
共享依赖（菱形结构）只被展开一次，不会按路径数量膨胀。

## 运行测试

```bash
python3 -m unittest test_depgraph -v
```

包含：两组指定正确性测试（同批撤边加反向边/顺序无关/菱形共享依赖；
两条新边 + 未修改长链构成的环/拒绝后无残留污染）、基础语义测试、
与朴素全量重算对照的随机差分测试，以及性能测试（10 万节点链 +
5000 个批次，固定随机种子，排除初始化后合计边检查次数 < 200 万，
计数器 `edge_checks` 覆盖增删边与前向/反向搜索中对辅助入边结构的
全部检查，含重复检查）。
