# PyForge 依赖图组件

`dependency_graph.py` 提供 `DependencyGraph`：固定节点集合上的有向依赖图
（边 A→B 表示 A 依赖 B），只维护当前依赖；版本、权限等发布字段由调用方验证。

## 接口

- `DependencyGraph(nodes, dependencies)`：从无环图创建，构造时做一次全图
  拓扑分级（迭代式 Kahn）。每节点直接依赖 ≤15，违反或有环抛 `ValueError`。
- `replace_batch(changes)`：`changes` 为 `{节点: 新直接依赖列表}`（≤100 个节点，
  空列表表示清除依赖）。成功返回 `None` 且整批生效；失败返回一个环
  （节点列表，首尾相同、中间不重复、每条边都真实存在于候选图中），
  本批不产生任何影响。未知节点/目标、出度超限抛 `ValueError`。
- `dependencies(node)`：返回当前已提交直接依赖的副本，修改返回值不影响组件。

## 批次原子性的依据

批次分两阶段作用于内部状态：

1. **先删**：删除本批涉及节点的全部旧边。删边不可能成环，此阶段始终安全。
2. **后加**：逐条加入新边，每条用增量环检测。任一时刻被检出的环只由
   “已删完旧边的图 + 部分新边”构成，而这些边全部属于最终候选图——
   加边不会破坏已存在的环，所以该环是候选图有环的有效证据。

因此接受 ⟺ 候选图无环，判定结果只取决于候选图本身，与批次条目排列无关。
拒绝时按撤销日志回滚：只恢复本批触到的 ≤100 个节点的旧依赖和被重排过
的节点的旧 rank（旧 rank 对旧图仍是合法拓扑序），不需要整图副本，
已提交状态与“本批从未发生”完全一致。

## 增量检查的依据（Pearce & Kelly 增量拓扑排序）

维护不变式：对每条边 a→b 有 `rank[a] < rank[b]`。加入新边 u→v 时：

- `rank[u] < rank[v]`：新边与拓扑序同向，不可能成环，O(1) 通过；
- 否则任何 v⇝u 的路径必然落在 rank 区间 `[rank[v], rank[u]]` 内，
  只在该区间内前向搜索（迭代式 DFS，带父指针）。到达 u 即按父指针
  重构出真实环路径；未到达则无环，随后把 u 的祖先组整体重排到 v 的
  后代组之前（复用原 rank 值），恢复不变式。

每批工作量只与受影响的 rank 区间成正比，不扫描全图、不保存全对可达关系；
共享依赖只会被 visited 集合合并，不按路径数量膨胀。所有搜索均为迭代式，
长度接近 10 万的链不会溢出调用栈。

`edge_checks` 计数器记录验证与索引维护中检查依赖边的总次数
（含重复检查、正/反邻接与增删 bookkeeping），供性能测试断言。

## 运行测试

```bash
python3 -m unittest -v     # 或 python3 -m pytest -q
```

测试内容：

- **正确性组 1**：同批撤 A→B、加 B→A（逐项作用会暂时成环但最终无环，
  两种输入顺序都必须成功）；菱形共享依赖不误判为环，真实环仍被检出。
- **正确性组 2**：构造必须同时使用两条新边和一段 5 万长未修改链才成立的环，
  校验拒绝及返回环的每条边；随后立即提交合法批次、再提交真正成环的批次，
  确认无残留依赖与索引污染。
- **性能测试**：10 万节点链 + 固定种子（20261004）的 5000 个单节点批次
  （保留链边 + 前半段节点向后半段加附加依赖），全部成功，且排除初始化后
  边检查总次数 < 200 万（实测约 1.5 万）。
